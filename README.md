# 字幕校对台 · Live Subtitle QC Console

面向直播运营团队的字幕校对工作台。现场字幕事件持续推送，网络抖动会造成**乱序、重复**，机器修订还可能**覆盖人工已确认的内容**——本工作台把这些情况全部可视化，并把最终裁决权交给运营人员。

全部数据在浏览器本地模拟，不依赖任何后端服务。

## 功能一览

- **三栏直播工作台**：直播预览（ON AIR 监视器 + 待播队列）、字幕时间线、事件流同屏呈现
- **乱序补齐**：字幕按序号排列，缺失片段留下明显空位（斜纹 + 虚线框 + 文字说明）；晚到片段自动补回
- **重复去重**：同一事件 ID 重发、或不同事件内容完全相同，都只记录日志，绝不生成第二条字幕
- **版本更新**：未锁定片段收到更高版本机器修订时直接应用，过期版本被忽略
- **锁定冲突**：人工修改并锁定后，机器修订不再静默覆盖，转为待裁决冲突——由运营选择「保留人工版本」或「接受机器修订」
- **可稳定重放的“网络抖动”场景**：内置 `101 → 103 → 103(重复) → 102(晚到) → 102 的机器修订 v2`，支持播放 / 暂停 / 单步 / 0.5–4× 倍速 / 重放；每次重放从干净状态开始，相同操作必然得到相同结果
- **版本化节目术语校对**：维护品牌名/人名/产品型号术语（原词、目标写法、语言、有效序号区间、说话人范围、同音词）。系统扫描当前字幕并按四类解释每条匹配依据——✅ 可自动建议、🔒 人工锁定冲突、🔊 同音歧义、➖ 不适用（含被更长术语遮蔽的重叠命中）；只给建议不直接替换，可逐条或批量接受，支持撤销/重做；术语表一改版本号旧建议立即失效重算，重复应用幂等，晚到片段只增量扫描；状态持久化到 localStorage，刷新可恢复
- **不只靠颜色区分状态**：播出中、缺口、重复、冲突、锁定均有图标 + 文字徽标（缺口另有斜纹图案），色盲友好

## 运行方式

要求 Node.js ≥ 18。

```bash
npm install       # 安装依赖
npm run dev       # 开发模式（默认 http://localhost:5173）
npm test          # 运行自动化测试（Vitest，59 个用例）
npm run build     # 生产构建（tsc 类型检查 + vite 打包到 dist/）
npm run preview   # 预览生产构建产物
```

## 快速体验：复现一次“锁定冲突”

1. 点击底部「▶ 播放」，观察 `#101` 到达、`#103` 乱序到达留下 `#102` 缺口、重复 `#103` 被去重、`#102` 晚到自动补回；
2. 在 `#102` 补齐后（+4.5s）、修订到达前（+10s）点击「⏸ 暂停」；
3. 在时间线上「✏️ 修改」`#102` 的文本，然后点击「🔒 锁定」；
4. 点击「▶ 播放」继续，机器修订 v2 到达 → 顶部出现**待裁决冲突**面板；
5. 选择「✋ 保留人工版本」或「🤖 接受机器修订」，观察时间线与事件流的变化；
6. 随时点击「↺ 重放」回到干净状态重新开始；也可以用「⏭ 单步」逐事件精确推进。

## 架构说明

```
src/
├── types.ts            领域模型（事件 / 片段 / 冲突 / 日志 / 术语历史 / 状态）
├── consoleReducer.ts   纯函数状态机：去重、补齐、版本裁决、锁定冲突、术语应用、撤销重做、重置
├── glossary.ts         术语扫描引擎：词边界、最长匹配重叠消解、同音歧义、范围过滤、版本签名
├── glossaryReducer.ts  版本化术语表：增删改（版本单调递增）、停启用、独立撤销重做
├── storage.ts          localStorage 持久化与旧版本状态迁移（刷新恢复）
├── selectors.ts        派生数据：缺口、当前播出、待播队列等
├── scenario.ts         内置“网络抖动”场景脚本（逻辑时间戳，确定性数据）
├── player.ts           播放器：播放/暂停/单步/倍速/重放，调度器与时钟可注入
├── useSubtitleConsole.ts  React 装配层（双 reducer + Player + 按片段签名的增量扫描缓存）
├── components/         界面组件（预览 / 时间线 / 事件流 / 冲突面板 / 术语表 / 建议面板 / 播放控制）
└── __tests__/          Vitest 测试
```

**确定性设计**（“相同操作 → 相同结果”的保证）：

- reducer 是纯函数，不读时钟、不含随机数；事件自带逻辑时间戳；
- 播放器的调度器与时钟均可注入，测试中用手动时钟同步驱动；
- 「重放」= `reset` 动作（返回全新初始状态）+ 从头调度同一场景脚本。

**关键规则**：

| 情况 | 行为 |
| --- | --- |
| 相同事件 ID 再次到达 | 记「重复」日志，状态不变 |
| 同序号同版本同文本 | 记「重复」日志，状态不变 |
| 更低版本到达 | 记「过期」日志，状态不变 |
| 更高版本 + 未锁定 | 直接应用修订（若覆盖了未锁定的人工修改，会在日志中注明） |
| 更高版本 + 已锁定 | 登记待裁决冲突，人工内容原样保留 |
| 裁决「保留人工」 | 丢弃该机器修订，片段维持锁定 |
| 裁决「接受机器」 | 应用修订内容并解除锁定，片段交还机器流 |
| 术语原词命中且片段未锁定、无同音干扰 | 给出可接受建议，展示命中位置与依据，不自动替换 |
| 术语命中但片段已锁定 | 归为人工锁定冲突，任何补丁都不得改写锁定文本 |
| 同音词在片段中出现 | 归为同音歧义（原词并存时原词命中也降级），需人工判断 |
| 多个术语命中区间重叠 | 最长原词遮蔽较短者并解释；等长重叠保留两条交人工选择 |
| 批量接受建议 | 同一片段内右→左替换避免位移；整批只产生一个撤销单位 |
| 重复接受同一术语版本 | 幂等：不修改文本、不产生历史与日志 |
| 术语内容被修改 | 版本 +1，旧建议随术语签名变化整体失效并重新扫描 |
| 晚到片段到达 | 仅扫描该片段相关术语，未变片段的扫描结果引用复用 |
| 撤销/重做时片段已被机器修订 | 过期快照不覆盖新文本，撤销单位安全出栈 |

**播出规则**：当前播出字幕是从最小序号起连续完整的最长前缀末尾——缺口之后的片段即使已到达也只进入待播队列，直到缺口补齐。

## 自动化测试

`src/__tests__/` 共 59 个用例，覆盖需求要求的全部场景：

- **乱序补齐**：缺口出现/消失、播出序号不越过缺口、补齐日志
- **重复去重**：事件 ID 级去重、内容级去重，均不产生第二条字幕
- **版本更新**：未锁定片段应用修订、过期版本被忽略
- **锁定冲突**：不静默覆盖、锁定时禁止编辑、「保留人工」与「接受机器」两种裁决
- **术语扫描**：中英文词边界（GPU 不匹配 GPUs / M1GPU）、中文构词嵌套、多处命中、最长匹配遮蔽、等长重叠并存、锁定冲突、同音歧义、序号区间与说话人范围、停用、不适用解释
- **术语应用**：单条/批量（一个撤销单位）、多命中点替换、重叠补丁去重、幂等（重复接受不改文本）、锁定片段强制补丁也被拒绝、非法位置安全跳过
- **术语版本变化**：修改抬升版本号、旧建议 id 随签名失效、旧目标写法包含原词时不二次建议、机器修订后旧撤销快照不覆盖新文本
- **晚到片段**：增量扫描只算新片段、未变片段结果引用复用、范围外术语无结果
- **撤销/重做与重放**：批量整体回滚、新应用清空重做栈、reset 后与初始状态逐位相等
- **刷新恢复**：localStorage 往返一致、旧版本状态字段迁移、损坏 JSON 安全回退
- **播放器行为**：按时间表投递、暂停结算剩余时间、倍速重排程、单步与播放混用
- **App 冒烟**：完整组件树服务端渲染，新旧区块都在
