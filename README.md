# 字幕校对台 · Live Subtitle QC Console

面向直播运营团队的字幕校对工作台。现场字幕事件持续推送，网络抖动会造成**乱序、重复**，机器修订还可能**覆盖人工已确认的内容**——本工作台把这些情况全部可视化，并把最终裁决权交给运营人员。

全部数据在浏览器本地模拟，不依赖任何后端服务。

## 功能一览

- **三栏直播工作台**：直播预览（ON AIR 监视器 + 待播队列）、字幕时间线、事件流同屏呈现
- **乱序补齐**：字幕按序号排列，缺失片段留下明显空位（斜纹 + 虚线框 + 文字说明）；晚到片段自动补回
- **重复去重**：同一事件 ID 重发、或不同事件内容完全相同，都只记录日志，绝不生成第二条字幕
- **版本更新**：未锁定片段收到更高版本机器修订时直接应用，过期版本被忽略
- **锁定冲突**：人工修改并锁定后，机器修订不再静默覆盖，转为待裁决冲突——由运营选择「保留人工版本」或「接受机器修订」
- **版本化术语校对**（新增）：维护节目专用术语表（品牌名 / 人名 / 产品型号），术语含**原词、目标写法、语言、有效时间窗、说话人范围、同音词**；系统先扫描当前字幕并分类展示影响范围，运营再决定单条或批量接受——**从不直接批量替换**
- **可稳定重放的“网络抖动”场景**：支持播放 / 暂停 / 单步 / 0.5–4× 倍速 / 重放；每次重放从干净字幕状态开始，相同操作必然得到相同结果
- **不只靠颜色区分状态**：播出中、缺口、重复、冲突、锁定、术语分类均有图标 + 文字徽标（缺口另有斜纹图案），色盲友好

## 版本化术语校对

### 术语条目

每条术语包含：

| 字段 | 含义 | 缺省 |
| --- | --- | --- |
| `source` / `target` | 原词（被扫描写法）/ 目标写法 | 必填 |
| `lang` | 适用语言（如 zh-CN） | 不限制 |
| `speakers` | 适用说话人白名单 | 不限制 |
| `validFromMs` / `validToMs` | 节目时间轴上的有效区间（与片段时间窗按闭区间重叠判定） | 全程有效 |
| `homophones` | 同音词表（如「欣闻」之于「新闻」） | 无 |
| `enabled` | 停用后不参与扫描，但术语与版本保留 | 启用 |

### 扫描结果四分类（每条都附“匹配依据/排除理由”）

1. **🟢 可自动建议**：边界完整命中原词、语言/说话人/有效时间均在范围内、片段未锁定——预计算“替换后”文本，可单条、按片段或批量接受；
2. **🔒 人工锁定冲突**：命中原词但片段已锁定，绝不自动改写，需解锁后人工处理；
3. **🔊 同音歧义**：出现同音写法（哪怕同片段也出现了原词），一律保守处理，只提示人工听音确认；
4. **🚫 不适用片段**：语言 / 说话人 / 有效时间不符、与更高优先级（更长/更保守）术语重叠、或该术语当前版本已应用过——仅解释原因。

### 关键规则

- **边界匹配**：Latin/数字串要求词边界（`iPhone15` 不命中 `iPhone15ProMax` 内部、`AI` 不命中 `AIDE`）；中文无空格分词，相邻汉字不阻断（`晚间新闻` 可在 `收看晚间新闻直播` 中命中），包含关系交给重叠仲裁。
- **重叠术语**：按**每个出现位置**独立仲裁，优先级为「同音/锁定等保守类别 > 命中长度（更长更具体）> 位置 > id」；同词多处出现可部分采纳、部分排除，并在理由中说明。
- **术语版本化**：任何新增 / 更新 / 停用 / 删除都让全局 `termVersion` 递增，**旧建议整体失效后重新计算**；建议 key 内嵌术语版本，持有旧 key 的待执行接受操作自动作废。
- **幂等**：接受后片段记录 `termId -> 应用版本`，重复接受（或人工把原词改回后再扫）当前版本不再修改字幕；已应用术语的原词区间继续作为“遮蔽位”，防止包含在其中的其他短词二次修改；新版本术语可再次产生建议。
- **增量扫描**：新片段（含晚到补齐）到达时只扫描该片段，且只与文本相关的术语产生记录；机器修订只重扫对应片段并清空该片段旧文本上的应用记录。
- **撤销 / 重做**：字幕编辑、锁定、冲突裁决、术语维护、接受建议全部进入撤销历史（机器接收动作不入历史），最多 50 步；新操作会清空重做栈。
- **刷新恢复**：事实层（片段 / 去重记录 / 冲突 / 日志 / 术语表 / 术语版本）持久化到 localStorage；扫描缓存为派生数据不入库，恢复时重建；撤销栈不跨刷新保留。
- **重放保留术语资产**：`↺ 重放` 清空字幕侧全部状态（含扫描缓存与撤销栈），但保留节目术语表与术语版本。

## 运行方式

要求 Node.js ≥ 18。

```bash
npm install       # 安装依赖
npm run dev       # 开发模式（默认 http://localhost:5173）
npm test          # 运行自动化测试（Vitest，48 个用例）
npm run build     # 生产构建（tsc 类型检查 + vite 打包到 dist/）
npm run preview   # 预览生产构建产物
```

## 快速体验：复现一次“锁定冲突”

1. 点击底部「▶ 播放」，观察 `#101` 到达、`#103` 乱序到达留下 `#102` 缺口、重复 `#103` 被去重、`#102` 晚到自动补回；
2. 在 `#102` 补齐后（+4.5s）、修订到达前（+10s）点击「⏸ 暂停」；
3. 在时间线上「✏️ 修改」`#102` 的文本，然后点击「🔒 锁定」；
4. 点击「▶ 播放」继续，机器修订 v2 到达 → 顶部出现**待裁决冲突**面板；
5. 选择「✋ 保留人工版本」或「🤖 接受机器修订」，观察时间线与事件流的变化；
6. 随时点击「↺ 重放」回到干净字幕状态重新开始；也可以用「⏭ 单步」逐事件精确推进。

## 快速体验：术语校对

1. 播放场景后，打开「🧪 术语校对建议」：预置术语会立即给出分类结果（如「晚间新闻→《晚间新闻》」自动建议、限说话人/时间的术语显示不适用理由）；
2. 先看每条建议的**原文高亮、替换后预览与匹配依据**，再点「✅ 接受这条」「接受本片段全部」或顶部「批量接受全部」；
3. 在「📖 节目术语表」里更新某条术语（如改目标写法）→ 观察旧建议消失、按新版本重扫，事件流记录重扫统计；
4. 点「↶ 撤销 / ↷ 重做」回退或重放接受操作；刷新浏览器后字幕、术语表与建议自动恢复；
5. 给术语添加同音词（如术语「新闻→资讯」加同音词「欣闻」），观察出现同音写法时只提示「同音歧义」，不自动替换。

## 架构说明

```
src/
├── types.ts             领域模型（事件 / 片段 / 冲突 / 日志 / 版本化术语 / 匹配建议 / 快照）
├── consoleReducer.ts    纯函数状态机：接收裁决、锁定冲突、术语维护、接受建议、撤销重做、hydrate/reset
├── termScan.ts          纯函数术语扫描器：边界、范围（语言/说话人/时间）、同音、重叠仲裁、幂等遮蔽
├── selectors.ts         派生数据：缺口、当前播出、待播队列、术语列表、分类建议、撤销可用性
├── storage.ts           刷新恢复：可注入 Storage 的事实层持久化（扫描缓存不入库）
├── defaultTerms.ts      节目预置术语表
├── scenario.ts          内置“网络抖动”场景脚本（含说话人/语言/时间窗元数据）
├── player.ts            播放器：播放/暂停/单步/倍速/重放，调度器与时钟可注入
├── useSubtitleConsole.ts React 装配层（useReducer + Player 单例 + 持久化恢复/落盘）
├── components/          界面（预览 / 时间线 / 事件流 / 冲突面板 / 术语表 / 术语建议 / 播放控制）
└── __tests__/           Vitest 测试
```

**确定性设计**（“相同操作 → 相同结果”的保证）：

- reducer 与扫描器都是纯函数，不读时钟、不含随机数；事件自带逻辑时间戳；
- 新建术语的 id 与术语版本由状态机单调分配（`term-{n}`），重放结果逐位一致；
- 播放器的调度器与时钟均可注入，测试中用手动时钟同步驱动；
- 「重放」= `reset` 动作（清空字幕、扫描缓存与撤销栈，保留术语表）+ 从头调度同一场景脚本。

**字幕侧既有规则**：

| 情况 | 行为 |
| --- | --- |
| 相同事件 ID 再次到达 | 记「重复」日志，状态不变 |
| 同序号同版本同文本 | 记「重复」日志，状态不变 |
| 更低版本到达 | 记「过期」日志，状态不变 |
| 更高版本 + 未锁定 | 直接应用修订（若覆盖了未锁定的人工修改，会在日志中注明），并重扫该片段 |
| 更高版本 + 已锁定 | 登记待裁决冲突，人工内容原样保留 |
| 裁决「保留人工」 | 丢弃该机器修订，片段维持锁定 |
| 裁决「接受机器」 | 应用修订内容并解除锁定，清空旧术语应用记录后重扫 |

**播出规则**：当前播出字幕是从最小序号起连续完整的最长前缀末尾——缺口之后的片段即使已到达也只进入待播队列，直到缺口补齐。

## 自动化测试

`src/__tests__/` 共 48 个用例：

- **乱序补齐**：缺口出现/消失、播出序号不越过缺口、补齐日志
- **重复去重**：事件 ID 级去重、内容级去重，均不产生第二条字幕
- **版本更新**：未锁定片段应用修订、过期版本被忽略
- **锁定冲突**：不静默覆盖、锁定时禁止编辑、「保留人工」与「接受机器」两种裁决
- **无残留重放**：reset 后与初始状态逐位相等（无术语时）；同操作序列重放结果一致；播放器两轮完整播放终态一致
- **播放器行为**：按时间表投递、暂停结算剩余时间、倍速重排程、单步与播放混用
- **术语校对**（32 个）：
  - 边界匹配（Latin/数字词边界、中文相邻、多处替换）
  - 语言 / 说话人 / 有效时间范围（含闭区间相接、缺元数据、无噪声建议）
  - 同音歧义（只提示不替换、原词与同音词同时出现仍保守）
  - 重叠术语（长词胜出、短词独立出现仍可建议、同音优先占位、逐位置仲裁）
  - 锁定字幕（锁定冲突分类、批量接受不触碰锁定项、解锁后转自动）
  - 术语版本变化（版本递增、旧建议失效、旧 key 作废、停用/启用/删除重扫）
  - 晚到片段（只生成自己的扫描、只与相关术语产生记录、修订只重扫该片段并清空应用记录）
  - 幂等（重复接受引用不变、人工改回不重建议、长词应用后遮蔽短词）
  - 单条 / 批量接受（跨片段确定性顺序、只改指定条目）
  - 撤销 / 重做（恢复文本与建议、重做栈失效、机器动作不入历史、空栈安全）
  - 刷新恢复（落盘/重建扫描缓存/清空撤销栈/脏数据回退）
  - reset 与术语资产（清空字幕保留术语、无术语时逐位等于初始状态）
